# 대식이

광운대 주변 음식점 추천 지도입니다. 광운대 학생이 남긴 기록으로 학교 근처 밥집을 찾는 웹 앱입니다. 지도에서 가게를 보고, 걸어서 얼마나 걸리는지와 1인 가격으로 거를 수 있습니다.

2026년 2학기 오픈소스소프트웨어및실습 7조(team07) 프로젝트입니다.

- 제안 이슈: [kw-hdi-lab/oss2026-project#7](https://github.com/kw-hdi-lab/oss2026-project/issues/7) (확정됨)
- 배포 주소: https://daesik.duckdns.org (예전 주소 https://kwfood.duckdns.org 로도 열립니다)
- 지금 상태: 첫 화면에 학교 주변 지도가 나오고, 가게를 검색해서 고른 뒤 한 줄 추천을 써서 저장하면 그 가게가 지도에 표시되고 눌러서 추천을 볼 수 있습니다. 가게 검색 화면에서 교내 인증을 할 수 있고, 검색은 기록에 적힌 메뉴로도 됩니다. 같이 정하기는 방을 만들어 투표하고 마감한 뒤 다녀왔어요를 남기는 것까지 됩니다. 한 줄 추천은 신고할 수 있고, 신고된 글은 LLM이 악의적인지 판단합니다. 가게 상세의 또 갈래요 비율과 가격은 최근 기록일수록 크게 반영합니다. 지도 왼쪽 칸에서 가격 상한, 음식 종류, 태그로 거를 수 있고, 가게 상세에서 "또 갈래요"나 "글쎄요"를 남기고 웨이팅과 자리를 제보할 수 있습니다. 기록을 꾸준히 남기면 칭호가 붙습니다. LLM(Gemini)은 칸 채우기, 작성 전 검사, 신고된 글 판단, 검색어 넓히기, 검색 결과 순서, 말로 찾기, 가게 요약, 메뉴 뽑기, 종류별 보통 가격에 씁니다. 시드 데이터는 아직입니다. 아래 "피드백을 받고 바꾼 것"부터는 팀 합의 전 초안입니다. 11/19 중간발표에서 받은 질문과 그래서 바꾸려는 것은 "중간발표에서 받은 질문"에 적었습니다.

## 확정된 제안

제안 이슈의 앞부분을 옮겨 적었습니다. 계산 규칙과 서버, LLM 칸은 이슈 원문에 있습니다.

**한 줄 소개**
광운대 학생이 직접 남긴 추천글을 지도에서 보고, 거리와 가격, 작성자 구분으로 걸러 학교 주변 음식점을 찾는 웹 앱

**누가, 언제, 무엇 때문에 불편한가**
- 학교 주변 가게를 잘 모르는 광운대 신입생과 복학생이 대상
- 신입생은 아는 선배가 없으면 어디가 괜찮은지 물어볼 곳이 없음
- 복학생은 휴학하는 동안 가게가 새로 생기거나 없어져서 예전에 알던 정보가 맞지 않음

**지금은 어떻게 해결하고 있나**
- 선후배 입소문: 아는 사람이 있어야만 정보를 얻을 수 있음
- 에브리타임 같은 커뮤니티 글: 금방 묻혀서 찾기 어렵고, 오래된 글에는 폐업한 가게가 섞여 있음
- 네이버지도, 카카오맵 리뷰: 학생이 아닌 손님의 리뷰와 광고성 리뷰가 섞여 있고, 도보 거리나 1인 가격 같은 학생 기준으로 거를 수 없음

**가장 먼저 완성할 기능**
지도에서 가게를 검색해 고른 뒤 별점, 1인 가격, 추천글, 작성자 구분을 입력하면, 그 가게 마커를 눌렀을 때 추천글 목록과 평균 별점이 표시됨

## 피드백을 받고 바꾼 것

제안은 그대로 확정됐지만 교수님이 이런 의견을 주셨습니다.

> 이 서비스는 추천글이 얼마나 쌓이느냐에 따라 거의 모든 것이 결정될 것 같다. 지금은 팀원들이 시드 데이터를 넣는 것 외에는 학생들이 여기에 글을 남길 이유가 잘 보이지 않는다. 에브리타임에 한 줄 쓰는 것보다 입력할 것도 많다.

맞는 말이라서 "누가 왜 쓰는가"부터 다시 잡았습니다.

읽는 사람은 신입생과 복학생이지만, 쓸 수 있는 사람은 학교를 1년 넘게 다닌 재학생입니다. 재학생이 후배를 위해 시간을 내 주기를 기대하는 건 무리입니다. 그래서 재학생이 원래 하던 일, 그러니까 친구들과 "오늘 뭐 먹지"를 정하는 일을 앱에서 하게 하고 그 결과가 기록으로 남게 하려고 합니다.

입력도 줄였습니다. 처음에는 별점, 가격, 추천글, 작성자 구분을 다 받으려 했는데, 이건 에브리타임에 한 줄 쓰는 것보다 귀찮습니다.

- 별점 1~5점은 없애고 "또 갈래요"와 "글쎄요" 버튼 두 개로 바꿉니다.
- 글을 남길 때는 한 줄만 씁니다. 가격과 태그는 LLM이 그 한 줄에서 뽑아 칸에 채워 줍니다. 처음 제안에서 LLM은 추천글을 요약하는 데 쓰려 했는데, 이쪽으로 옮겼습니다.
- 작성자 구분(신입생, 복학생, 학번)은 첫 버전에서 뺍니다. 확정된 제안의 한 줄 소개에는 들어 있던 기능이라, 여유가 생기면 다시 넣을지 정합니다.

## 중간발표에서 받은 질문

11/19 중간발표에서 받은 질문과, 그래서 바꾼 것입니다. 표에 적은 것은 모두 만들었습니다.

| 받은 질문 | 바꾼 것 |
| --- | --- |
| 가게 사장님이 자기 가게를 홍보하면 어떻게 하나. 학생 인증은 없나 (공감 5) | 교내 인증을 넣습니다. 학교 안에서 인증한 익명 ID의 기록만 비율과 순위에 넣습니다 |
| 시크릿 창을 열 때마다 새 사람이 돼서 "또 갈래요"를 계속 누를 수 있지 않나 | 위와 같습니다. 새 창을 열면 학교 안에서 다시 인증해야 합니다 |
| 접속할 때마다 인증해야 하나 | 한 번 인증하면 그 브라우저에서 30일 동안 유지합니다 |
| 제육을 검색했는데 윤스쿡이 안 나온다. 대표 메뉴가 아니어도 찾을 수 있어야 한다 (공감 3) | 한 줄 추천에 먹은 메뉴를 받고, 검색할 때 기록에 적힌 메뉴도 같이 찾습니다. 결과가 적으면 LLM이 "제육"을 "제육볶음"처럼 넓혀서 한 번 더 찾습니다 |
| 1년 전 기록과 어제 기록이 같은 무게로 들어가지 않나 | 기록에 시간 가중치를 줍니다. 90일마다 무게가 반으로 줄고 1년이 지나면 넣지 않습니다. 가게마다 마지막 기록 날짜도 보여 줍니다 (R14) |
| 악의적인 글이나 허위 사실은 어떻게 막나 | 신고 버튼을 두고, 신고가 들어오면 LLM이 그 글이 악의적인지 판단합니다. 교내 인증한 3명이 신고하거나 LLM이 악의적이라고 하면 숨깁니다 (R15) |
| LLM이 가격을 잘못 읽으면 필터 결과가 틀리지 않나 | LLM이 뽑은 값은 칸에만 채우고 사용자가 확인해서 저장합니다. 가격이 없는 한 줄이면 칸을 비워 두고, 그 기록은 가격 평균에 넣지 않습니다. 글에 적힌 가격과 가격 칸이 크게 다르면 그 가격은 보류하고 평균에서 뺍니다 (R17) |
| 지도에서 기록이 몇 건인지 바로 보이면 좋겠다 | 마커에 기록 수를 표시합니다 |
| 카톡방에도 투표가 있는데 왜 여기서 정하나 | 카톡 투표는 후보를 직접 적어야 하고 가격과 거리가 안 보입니다. 여기서는 필터로 후보를 뽑고, 정한 결과가 기록으로 이어집니다. 이걸로 충분한 답이 되는지는 아직 자신이 없습니다 |
| 가게가 지금 붐비는지, 자리가 있는지도 알 수 있나 | 가게의 실시간 정보를 받을 곳은 없어서, 학생이 "웨이팅 있어요"나 "자리 있어요"를 제보하면 30분 동안 보여 줍니다 (R16) |

학생 인증을 로그인 없이 하는 방법도 찾아봤습니다. KLAS나 도서관 앱은 밖에서 붙일 수 있는 방법을 찾지 못했습니다. 아이디를 대신 받거나 학교 메일로 확인하는 것은 로그인과 개인정보 수집이 돼서 수업 조건에 맞지 않습니다. 그래서 "학생인지"가 아니라 "학교에 와 있는지"를 확인하기로 했습니다.

## 어떻게 쓰게 되나

### 기록을 남기는 쪽

세 가지 방법이 있고, 전부 로그인 없이 됩니다.

**다녀왔어요.** 지도에서 가게를 누르고 "또 갈래요"나 "글쎄요"를 누릅니다. 이게 끝입니다.

**한 줄 추천.** 가게를 고르고 한 줄을 씁니다.

```
제육 7천원인데 양 많음 혼밥하기 좋음
```

서버가 이 문장을 LLM에 보내서 가격 7000원, 태그 "양 많음"과 "혼밥"을 받아 칸에 채웁니다. 맞는지 보고 저장을 누르면 됩니다. 음식 종류는 가게를 검색할 때 따라오는 분류를 쓸 생각이라 따로 입력받지 않습니다.

먹은 메뉴 칸은 따로 있고 비워 둬도 됩니다. 적어 두면 메뉴로 가게를 찾을 때와 요즘 많이 먹는 메뉴에 쓰입니다.

저장하기 전에는 전화번호, 욕설, 광고 같은 내용이나 글과 다른 가격이 있는지 알려 주고, 그래도 저장할지 묻습니다. 글에 "7천원"이라고 쓰고 가격 칸에 70,000을 넣었으면 7,000원으로 고칠지 묻습니다.

**같이 정하기.** 한 명이 방을 만들어 링크를 단톡방에 올리면, 각자 들어와서 후보 가게에 투표합니다. 방을 만든 사람이 마감하면 표가 가장 많은 가게로 정해집니다. 다녀온 뒤 같은 링크에서 "또 갈래요"나 "글쎄요"를 누르면 그게 기록이 됩니다. 실시간 통신은 쓰지 않고, 화면이 몇 초마다 서버에 다시 물어봐서 투표 현황을 갱신합니다. 방을 만들 때 "8천원 이하로 혼밥하기 좋은 데"처럼 말로 후보를 찾을 수도 있습니다.

**칭호.** 교내 인증하고 남긴 기록이 쌓이면 칭호가 붙습니다(R18). 1개 "첫 숟갈", 5개 "단골", 15개 "맛잘알", 30개 "대식가"이고, 한 줄 추천 옆에 쓴 사람의 칭호가 보입니다.

### 교내 인증

기록은 누구나 남길 수 있지만, 비율과 순위에는 교내 인증을 한 익명 ID의 기록만 들어갑니다. 인증하지 않은 사람의 한 줄 추천은 보이기는 하고 "교내 인증" 표시가 붙지 않습니다.

학교 안에서 인증 버튼을 한 번 누르면 됩니다. 아래 둘 중 하나에 해당하면 통과합니다.

- 브라우저가 알려 준 위치가 학교 기준점에서 정해 둔 반경 안일 때
- 학교 와이파이로 접속했을 때 (서버가 본 접속 IP가 학교 대역일 때)

한 번 인증하면 그 브라우저에서 30일 동안 유지됩니다. 서버는 좌표와 IP를 판정에만 쓰고 저장하지 않습니다.

이 방법으로 확인되는 것은 "학생이다"가 아니라 "학교에 와 있다"입니다. 브라우저 위치는 속일 수 있고, 학교 와이파이는 학생이 아니어도 쓸 수 있습니다. 가짜 기록을 완전히 막지는 못하고, 학교에 직접 와야만 순위에 영향을 줄 수 있게 해서 한 사람이 순위를 흔들기 어렵게 하려는 것입니다.

### 가게를 찾는 쪽

지도를 열면 기록이 있는 가게 중 학교에서 걸어서 15분 안쪽인 곳이 보입니다. 1인 가격 상한, 음식 종류, 태그로 거를 수 있고, 가게를 누르면 몇 번 기록됐는지, 또 가겠다는 사람이 얼마나 되는지, 한 줄 추천이 나옵니다.

아직 기록이 없는 가게는 지도에 나오지 않습니다. 검색해서 찾은 뒤 첫 기록을 남기면 그때부터 지도에 나옵니다.

마커에는 기록 수가 같이 표시됩니다. 가게는 이름뿐 아니라 기록에 적힌 메뉴로도 찾을 수 있고, 카페도 나옵니다. "제육"을 검색하면 제육을 먹었다는 기록이 있는 가게가 같이 나옵니다.

가게 상세에는 한 줄 추천들을 모은 요약, 30분 안에 들어온 웨이팅과 자리 제보가 보입니다. 검색 화면 위에는 요즘 많이 먹는 메뉴가 나오고, 누르면 그 메뉴로 검색합니다.

### ChatGPT에 물어보는 것과 다른 점

- 기록은 학교에 다니는 사람이 실제로 다녀와서 남긴 것이고 계속 쌓입니다. 순위에는 교내 인증을 한 기록만 들어갑니다. 새로 생긴 가게나 없어진 가게도 여기에 반영됩니다.
- 같이 정하기는 여러 명이 같은 방에 표를 넣고 같은 결과를 보는 일이라 한 사람과 대화하는 ChatGPT로는 안 됩니다.

제안 단계에서 "구글 폼으로 글을 모아 CSV를 ChatGPT에 올리면 똑같다"는 지적을 받았습니다. 그 방법은 누군가 글을 모으고 정리해서 다시 올려야 합니다. 여기서는 밥집을 정하는 과정에서 기록이 생기고, 남기자마자 지도에 보입니다.

| 11/19 중간발표 | 가게 검색, 한 줄 추천 저장(LLM 없이 직접 입력), 지도에서 가게를 눌러 추천 보기 |
| 11/26 (13주차) | 필터와 정렬, 다녀왔어요 버튼, LLM으로 칸 채우기, 같이 정하기, 교내 인증, 먹은 메뉴와 메뉴로 찾기 |

중간발표까지는 맨 윗줄 하나만 끝까지 되게 만듭니다. 검색해서 고르고, 한 줄 남기고, 지도에서 확인하는 것까지입니다. 중간발표 때는 저장까지 됐고, 지도에서 확인하는 부분은 11/26 묶음과 같이 마무리합니다.

같이 정하기는 피드백에 대한 가장 중요한 답인데 만들 화면과 API가 제일 많습니다. 11/26까지 다 못 하면 투표와 마감까지만 먼저 넣습니다.

중간발표 뒤에 11/26까지 할 일이 늘었습니다. 다 못 하면 질문을 가장 많이 받은 교내 인증과 메뉴로 찾기를 먼저 합니다.

11/26 기준으로 표의 11/26 줄과 12/3 줄의 신고와 숨김까지 들어왔습니다. 남은 것은 시드 데이터 정리입니다.

최종 평가는 발표 없이 배포된 주소로 한다고 공지됐습니다. 처음 들어온 사람이 설명 없이 써 볼 수 있어야 하니, 첫 화면에 시드 데이터가 보이게 하고 기록 남기기 버튼을 지도 화면에 바로 둡니다.

## 계산 규칙

화면 코드와 다른 파일에 함수로 두고, 화면 없이 테스트합니다. 규칙마다 정상, 경계값, 잘못된 입력 테스트를 씁니다.

| 번호 | 규칙 |
| --- | --- |
| R1 | 도보 시간(분) = 학교 기준점에서 가게까지 직선거리 / 67m, 올림. 직선거리라 실제보다 짧게 나오는 어림값 |
| R2 | 도보 시간이 15분을 넘으면 지도와 목록에서 제외. 15분은 포함 |
| R3 | 필터: 1인 가격 상한, 음식 종류, 태그. 가게 가격은 한 줄 추천에 적힌 가격들의 평균이고, 가격이 하나도 없는 가게는 가격 필터를 걸면 빠짐. 가게 태그는 추천에 한 번이라도 나온 태그 |
| R4 | 또 가겠다는 비율 = "또 갈래요" 수 / ("또 갈래요" + "글쎄요") 수. 한 줄 추천은 여기에 세지 않음. 응답이 3개 미만이면 비율 대신 "기록 부족" |
| R5 | 정렬: 비율 높은 순, 같으면 도보 시간 짧은 순. "기록 부족"인 가게는 맨 뒤 |

## 서버

```
브라우저 (HTML, CSS, JavaScript, 카카오맵 SDK)
    |  fetch
Express 서버
    |-- 계산 규칙 함수
    |-- 저장 모듈 --> JSON 파일

```

### 저장하는 것

JSON 파일에 저장합니다.

- 가게: 카카오 장소 ID, 이름, 위도, 경도, 분류. 기록이 한 번이라도 남은 가게만
- 한 줄 추천: 가게, 문장, 가격, 태그, 익명 ID, 시각
- 응답: 가게, 또 갈래요 여부, 익명 ID, 방 코드(방에서 남긴 경우), 시각
- 방: 코드, 후보, 표, 마감 여부, 정해진 가게, 만든 사람의 익명 ID
- 시드 데이터: 팀원이 직접 가 본 가게. `data/seed/`에 넣어 저장소에 포함

중간발표 뒤에 더한 것입니다.

- 교내 인증: 익명 ID, 인증한 시각, 방법(위치 또는 와이파이). 좌표와 IP는 저장하지 않음
- 한 줄 추천에 먹은 메뉴
- 한 줄 추천과 응답에, 저장할 때 교내 인증 상태였는지
- 신고: 어느 한 줄 추천인지, 신고한 익명 ID, 시각
- 한 줄 추천에 붙는 것: 숨김 표시, LLM의 판단 결과, LLM이 뽑은 메뉴
- 가게에 붙는 것: LLM이 만든 요약
- 지금 상황 제보: 가게, 종류(웨이팅 또는 자리), 익명 ID, 시각. 하루가 지나면 지움
- 가게 종류별 보통 1인 가격 범위: LLM에게 받은 값. 일주일 동안 씀

파일을 읽고 쓰는 코드는 저장 모듈(`server/store.js`) 한 곳에만 둡니다. 지금은 EC2의 볼륨에 파일로 남기고 있고, 나중에 저장 방식을 바꾸게 되더라도 이 파일만 고치면 되게 하려는 것입니다. 지금은 가게, 한 줄 추천, 응답, 방, 교내 인증, 신고, 지금 상황 제보, 보통 가격 범위를 저장합니다.

API 키는 서버 환경 변수로만 두고 저장소에 올리지 않습니다. 브라우저에서 쓰는 카카오맵 JavaScript 키도 코드에 적지 않고 서버가 `/api/config`로 넘겨줍니다. 이 키는 브라우저에 보이는 값이라 카카오 디벨로퍼스에서 허용 도메인을 걸어 둡니다.

## LLM

Gemini API를 씁니다. 서버에서 LLM을 부르는 코드는 `server/llm.js` 한 곳이고, 키는 다른 키처럼 서버 환경 변수(`GEMINI_API_KEY`)로만 둡니다. 기본 모델은 `gemini-3.5-flash-lite`이고 `GEMINI_MODEL`로 바꿀 수 있습니다.

쓰는 곳은 여덟 군데이고, 모두 같은 원칙을 따릅니다.

- LLM은 글을 읽고 정리하는 데만 쓰고, 순위, 숨김, 거르기 같은 결정은 규칙 함수가 합니다.
- 사용자가 쓴 글은 따로 감싸서 보내고, 그 안에 적힌 지시는 따르지 말라고 문장에 적어 둡니다.
- 받은 답은 정해 둔 모양과 범위만 통과시킵니다.
- 실패하거나 키가 없거나 한도를 넘으면 그 기능만 빠지고 나머지는 그대로 동작합니다.
- 익명 ID는 보내지 않습니다.

| 쓰는 곳 | LLM이 하는 일 | LLM이 없을 때 |
| --- | --- | --- |
| 칸 채우기 (`POST /api/reviews/draft`) | 한 줄에서 가격과 태그를 뽑음 (R10) | 직접 입력 |
| 작성 전 검사 (`POST /api/reviews/check`) | 욕설, 광고, 근거 없는 단정을 찾음 | 전화번호, 이메일, 학번과 가격(R17)만 규칙으로 검사 |
| 신고된 글 판단 (`POST /api/reports`) | 신고된 글이 악의적인지 판단 | 신고 수로만 숨김 (R15) |
| 검색어 넓히기 (`GET /api/places/search`) | 결과가 적을 때 "제육"을 "제육볶음"처럼 넓힘 | 원래 결과만 |
| 검색 결과 순서 (`GET /api/places/search`) | 가게 이름과 분류를 보고 검색어의 음식이 대표 메뉴일지 짐작함. 순서는 규칙이 정함 | 이름이나 분류에 검색어가 있는 가게만 위로 |
| 말로 찾기 (`POST /api/places/ask`) | "8천원 이하 혼밥"을 필터 값으로 바꿈 | 필터를 직접 고름 |
| 가게 요약 (`GET /api/places/:id`) | 한 줄 추천들을 한 문장으로 정리 | 요약 없이 추천 목록만 |
| 메뉴 뽑기 (`GET /api/trends`) | 한 줄 추천에서 메뉴 이름을 뽑음. 세는 것은 규칙 | 이미 뽑아 둔 것과 먹은 메뉴 칸에 적힌 것만 셈 |
| 보통 가격 범위 (R17) | 가게 종류별 1인 가격의 보통 범위를 알려 줌 | 글, 같은 가게의 다른 가격과만 비교 |

호출 수를 줄이려고 결과를 저장해 둡니다. 요약은 추천이 바뀔 때만, 메뉴는 추천마다 한 번, 판단은 글마다 한 번, 검색어 넓히기, 검색 결과 순서, 말로 찾기는 같은 문장이면 하루, 보통 가격 범위는 일주일 동안 다시 묻지 않습니다. 서버 전체로는 하루 2,000번, 같은 접속 IP는 1시간에 40번까지만 부릅니다(`shared/usageLimit.js`, `LLM_DAILY_LIMIT`).

아래는 그중 두 곳을 자세히 적은 것이고, 나머지의 형식은 `docs/api.md`에 있습니다.

신고된 글 판단 (`POST /api/reports`, 됨)

- 보내는 것: 가게 이름, 신고된 한 줄 추천. 익명 ID는 보내지 않습니다.
- 받는 것: `{ "verdict": "malicious", "reason": "전화번호가 있음" }`. `verdict`는 `malicious`, `ok`, `unsure` 중 하나
- 받은 값은 `shared/moderation.js`로 검사하고, 숨길지는 R15가 정합니다. LLM 혼자서는 신고 없이 글을 숨기지 못합니다.
- 글마다 처음 신고가 들어올 때 한 번만 묻고 결과를 저장해 둡니다. 무료 한도를 아끼려는 것입니다.
- 글 안에 적힌 지시는 따르지 말고 판단만 하라고 문장에 적어 둡니다.
- 호출이 실패하거나 키가 없으면 신고 수로만 정합니다.

칸 채우기 (`POST /api/reviews/draft`, 됨)

- 보내는 것: 사용자가 쓴 한 줄, 가게 이름과 분류, 태그 목록
- 받는 것: `{ "price": 7000, "tags": ["양 많음", "혼밥"] }`
- 받은 값은 R10으로 걸러서 입력 칸에 채웁니다. 사용자가 저장을 눌러야 반영됩니다. 가격이 없는 한 줄이면 가격 칸은 비워 둡니다.
- 먹은 메뉴 칸은 아직 채우지 않습니다.
- 호출이 실패하거나 한도를 넘으면 칸을 비워 둡니다. 직접 입력해서 저장할 수 있고, 지도, 필터, 투표는 LLM을 쓰지 않습니다.

가게 추천이나 순위는 LLM에 맡기지 않고 저장된 기록과 위 규칙으로만 계산합니다.

## 배포

https://daesik.duckdns.org 에 올라가 있습니다. 만든 순서와 다시 올리는 방법은 [docs/deploy.md](docs/deploy.md)에 있습니다.

- AWS EC2 한 대에서 Docker 컨테이너로 Express 서버를 실행합니다. 메모리는 512MB로 제한했습니다.
- 앞에 nginx를 두고 https를 처리합니다. 인증서는 Let's Encrypt에서 받았고 자동으로 갱신됩니다.
- 데이터 폴더는 컨테이너 밖 볼륨에 두고 환경 변수 `DATA_DIR`로 연결합니다. 컨테이너를 새로 만들어도 기록이 남습니다.
- API 키는 서버의 `.env`에만 있고 저장소와 이미지에는 들어가지 않습니다.
- 서버에는 SSH 포트를 열지 않고 AWS Session Manager로 접속합니다.
- PR을 열면 GitHub Actions가 테스트를 돌립니다. 배포는 자동이 아니고, main에 합친 뒤 서버에 접속해서 직접 다시 올립니다. 자동으로 올라가게 하는 것은 수업 조건(자동 배포 서비스 금지)에 걸리는지 교수님께 확인한 뒤 정합니다.
- 카카오맵 JavaScript 키에는 배포 주소와 `http://localhost:3000`을 허용 도메인으로 등록해 뒀습니다.

## 개인정보

- 회원가입과 로그인이 없고, 이름, 학번, 연락처를 받지 않습니다.
- 브라우저에 처음 들어오면 무작위 익명 ID를 만들어 브라우저에 저장합니다. 같은 가게에 여러 번 기록하는 것을 막고, 투표를 한 사람 한 표로 세고, 방을 만든 사람을 알아보는 데 씁니다.
- 브라우저 저장소를 지우면 새 ID가 되므로 중복 기록을 완전히 막지는 못합니다.
- 한 줄 추천은 누구나 볼 수 있어서, 입력 칸에 이름이나 연락처를 쓰지 말라고 안내합니다.
- 교내 인증은 브라우저 위치와 접속 IP를 판정에만 쓰고 저장하지 않습니다. 저장하는 것은 어느 익명 ID가 언제 인증됐는지뿐입니다.
- 위치는 인증 버튼을 누르고 브라우저의 권한 요청을 허락했을 때만 받습니다. 거절해도 기록을 보고 남길 수 있습니다.
- nginx 접속 기록에는 지금도 접속 IP가 남습니다. 서버 운영용 기록이고 서비스에 저장하는 기록과 연결하지 않습니다.
- 위치와 접속 IP를 이렇게 쓰는 것이 수업의 개인정보 조건에 맞는지는 교수님께 확인하려고 합니다.
- LLM(Gemini)에는 한 줄 추천의 글, 가게 이름과 종류, 검색어만 보내고 익명 ID는 보내지 않습니다.
- 칭호는 익명 ID로 세고, 화면에는 칭호만 내보냅니다.
- 지금 상황 제보는 하루가 지나면 지웁니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```
npm install
cp .env.example .env    # 윈도우 명령 프롬프트에서는 copy .env.example .env
npm start
```

http://localhost:3000 으로 들어가면 됩니다. `.env`에 넣을 값은 `.env.example`에 적혀 있습니다.

가게 검색을 쓰려면 `.env`의 `KAKAO_REST_API_KEY`에 카카오 디벨로퍼스의 REST API 키를 넣어야 합니다. 그 앱에서 카카오맵 사용 설정도 켜야 하고, 꺼져 있으면 검색이 안 됩니다. 키가 없어도 서버는 켜지고 검색만 오류 안내가 나옵니다.

첫 화면의 지도를 보려면 `KAKAO_JS_KEY`에 같은 앱의 JavaScript 키를 넣어야 합니다. 그 키의 JavaScript SDK 도메인에 `http://localhost:3000`이 등록돼 있어야 하고, 키가 없으면 지도 자리에 안내 문구가 나옵니다.

테스트는 `npm test`로 돌립니다. `tests` 폴더에서 이름이 `.test.js`로 끝나는 파일이 실행됩니다.

실행 중에 서버가 쓰는 데이터는 `data/runtime/`에 생기고 저장소에는 올라가지 않습니다.
