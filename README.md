# 광운대 주변 음식점 추천 지도

광운대 학생이 남긴 기록으로 학교 근처 밥집을 찾는 웹 앱입니다. 지도에서 가게를 보고, 걸어서 얼마나 걸리는지와 1인 가격으로 거를 수 있습니다.

2026년 2학기 오픈소스소프트웨어및실습 team07 프로젝트입니다.

- 제안 이슈: [kw-hdi-lab/oss2026-project#7](https://github.com/kw-hdi-lab/oss2026-project/issues/7) (확정됨)
- 배포 주소: 아직 없음 (14주차에 AWS EC2와 Docker로 배포 예정)
- 지금 상태: 서버 뼈대, 저장 모듈, 가게 검색(API와 화면), 한 줄 추천 검사 함수(R6)까지 올라와 있습니다. 한 줄 추천 저장과 지도는 만드는 중입니다. 아래 "피드백을 받고 바꾼 것"부터는 팀 합의 전 초안입니다.

## 확정된 제안

제안 이슈의 앞부분을 옮겨 적었습니다. 계산 규칙과 서버, LLM 칸은 이슈 원문에 있습니다.

**한 줄 소개**
광운대 학생이 직접 남긴 추천글을 지도에서 보고, 거리와 가격, 작성자 구분으로 걸러 학교 주변 음식점을 찾는 웹 앱

**누가, 언제, 무엇 때문에 불편한가**
- 학교 주변 가게를 잘 모르는 광운대 신입생과 복학생이 대상
- 신입생은 아는 선배가 없으면 어디가 괜찮은지 물어볼 곳이 없음
- 복학생은 휴학하는 동안 가게가 새로 생기거나 없어져서 예전에 알던 정보가 맞지 않음

**지금은 어떻게 해결하고 있나**
- 선후배 입소문: 아는 사람이 있어야만 정보를 얻을 수 있음
- 에브리타임 같은 커뮤니티 글: 금방 묻혀서 찾기 어렵고, 오래된 글에는 폐업한 가게가 섞여 있음
- 네이버지도, 카카오맵 리뷰: 학생이 아닌 손님의 리뷰와 광고성 리뷰가 섞여 있고, 도보 거리나 1인 가격 같은 학생 기준으로 거를 수 없음

**가장 먼저 완성할 기능**
지도에서 가게를 검색해 고른 뒤 별점, 1인 가격, 추천글, 작성자 구분을 입력하면, 그 가게 마커를 눌렀을 때 추천글 목록과 평균 별점이 표시됨

## 피드백을 받고 바꾼 것

제안은 그대로 확정됐지만 교수님이 이런 의견을 주셨습니다.

> 이 서비스는 추천글이 얼마나 쌓이느냐에 따라 거의 모든 것이 결정될 것 같다. 지금은 팀원들이 시드 데이터를 넣는 것 외에는 학생들이 여기에 글을 남길 이유가 잘 보이지 않는다. 에브리타임에 한 줄 쓰는 것보다 입력할 것도 많다.

맞는 말이라서 "누가 왜 쓰는가"부터 다시 잡았습니다.

읽는 사람은 신입생과 복학생이지만, 쓸 수 있는 사람은 학교를 1년 넘게 다닌 재학생입니다. 재학생이 후배를 위해 시간을 내 주기를 기대하는 건 무리입니다. 그래서 재학생이 원래 하던 일, 그러니까 친구들과 "오늘 뭐 먹지"를 정하는 일을 앱에서 하게 하고 그 결과가 기록으로 남게 하려고 합니다.

입력도 줄였습니다. 처음에는 별점, 가격, 추천글, 작성자 구분을 다 받으려 했는데, 이건 에브리타임에 한 줄 쓰는 것보다 귀찮습니다.

- 별점 1~5점은 없애고 "또 갈래요"와 "글쎄요" 버튼 두 개로 바꿉니다.
- 글을 남길 때는 한 줄만 씁니다. 가격과 태그는 LLM이 그 한 줄에서 뽑아 칸에 채워 줍니다. 처음 제안에서 LLM은 추천글을 요약하는 데 쓰려 했는데, 이쪽으로 옮겼습니다.
- 작성자 구분(신입생, 복학생, 학번)은 첫 버전에서 뺍니다. 확정된 제안의 한 줄 소개에는 들어 있던 기능이라, 여유가 생기면 다시 넣을지 정합니다.

## 어떻게 쓰게 되나

### 기록을 남기는 쪽

세 가지 방법이 있고, 전부 로그인 없이 됩니다.

**다녀왔어요.** 지도에서 가게를 누르고 "또 갈래요"나 "글쎄요"를 누릅니다. 이게 끝입니다.

**한 줄 추천.** 가게를 고르고 한 줄을 씁니다.

```
제육 7천원인데 양 많음 혼밥하기 좋음
```

서버가 이 문장을 LLM에 보내서 가격 7000원, 태그 "양 많음"과 "혼밥"을 받아 칸에 채웁니다. 맞는지 보고 저장을 누르면 됩니다. 음식 종류는 가게를 검색할 때 따라오는 분류를 쓸 생각이라 따로 입력받지 않습니다.

**같이 정하기.** 한 명이 방을 만들어 링크를 단톡방에 올리면, 각자 들어와서 후보 가게에 투표합니다. 방을 만든 사람이 마감하면 표가 가장 많은 가게로 정해집니다. 다녀온 뒤 같은 링크에서 "또 갈래요"나 "글쎄요"를 누르면 그게 기록이 됩니다. 실시간 통신은 쓰지 않고, 화면이 몇 초마다 서버에 다시 물어봐서 투표 현황을 갱신합니다.

### 가게를 찾는 쪽

지도를 열면 기록이 있는 가게 중 학교에서 걸어서 15분 안쪽인 곳이 보입니다. 1인 가격 상한, 음식 종류, 태그로 거를 수 있고, 가게를 누르면 몇 번 기록됐는지, 또 가겠다는 사람이 얼마나 되는지, 한 줄 추천이 나옵니다.

아직 기록이 없는 가게는 지도에 나오지 않습니다. 검색해서 찾은 뒤 첫 기록을 남기면 그때부터 지도에 나옵니다.

### ChatGPT에 물어보는 것과 다른 점

- 기록은 광운대 학생이 실제로 다녀와서 남긴 것이고 계속 쌓입니다. 새로 생긴 가게나 없어진 가게도 여기에 반영됩니다.
- 같이 정하기는 여러 명이 같은 방에 표를 넣고 같은 결과를 보는 일이라 한 사람과 대화하는 ChatGPT로는 안 됩니다.

제안 단계에서 "구글 폼으로 글을 모아 CSV를 ChatGPT에 올리면 똑같다"는 지적을 받았습니다. 그 방법은 누군가 글을 모으고 정리해서 다시 올려야 합니다. 여기서는 밥집을 정하는 과정에서 기록이 생기고, 남기자마자 지도에 보입니다.

| 언제까지 | 무엇을 |
| --- | --- |
| 11/19 중간발표 | 가게 검색, 한 줄 추천 저장(LLM 없이 직접 입력), 지도에서 가게를 눌러 추천 보기 |
| 11/26 (13주차) | 필터와 정렬, 다녀왔어요 버튼, LLM으로 칸 채우기, 같이 정하기 |
| 12/3 (14주차) | Docker로 실행, 배포, 시드 데이터 정리 |
| 12/10 이후 | 다른 팀 저장소에 기여, 상호평가, 개별 기여 보고서 |

중간발표까지는 맨 윗줄 하나만 끝까지 되게 만듭니다. 검색해서 고르고, 한 줄 남기고, 지도에서 확인하는 것까지입니다.

같이 정하기는 피드백에 대한 가장 중요한 답인데 만들 화면과 API가 제일 많습니다. 11/26까지 다 못 하면 투표와 마감까지만 먼저 넣습니다.

최종 평가는 발표 없이 배포된 주소로 한다고 공지됐습니다. 처음 들어온 사람이 설명 없이 써 볼 수 있어야 하니, 첫 화면에 시드 데이터가 보이게 하고 기록 남기기 버튼을 지도 화면에 바로 둡니다.

## 계산 규칙

화면 코드와 다른 파일에 함수로 두고, 화면 없이 테스트합니다. 규칙마다 정상, 경계값, 잘못된 입력 테스트를 씁니다.

| 번호 | 규칙 |
| --- | --- |
| R1 | 도보 시간(분) = 학교 기준점에서 가게까지 직선거리 / 67m, 올림. 직선거리라 실제보다 짧게 나오는 어림값 |
| R2 | 도보 시간이 15분을 넘으면 지도와 목록에서 제외. 15분은 포함 |
| R3 | 필터: 1인 가격 상한, 음식 종류, 태그. 가게 가격은 한 줄 추천에 적힌 가격들의 평균이고, 가격이 하나도 없는 가게는 가격 필터를 걸면 빠짐. 가게 태그는 추천에 한 번이라도 나온 태그 |
| R4 | 또 가겠다는 비율 = "또 갈래요" 수 / ("또 갈래요" + "글쎄요") 수. 한 줄 추천은 여기에 세지 않음. 응답이 3개 미만이면 비율 대신 "기록 부족" |
| R5 | 정렬: 비율 높은 순, 같으면 도보 시간 짧은 순. "기록 부족"인 가게는 맨 뒤 |
| R6 | 한 줄 추천 검사: 5~100자. 가격은 비워 두거나 1,000~100,000 사이 정수. 태그는 아래 목록에서 3개까지 |
| R7 | 같은 익명 ID는 같은 가게에 하루에 응답 한 번, 한 줄 추천 한 번. 하루는 한국 시간 기준 날짜 |
| R8 | 투표 집계: 표가 가장 많은 가게. 동점이면 도보 시간이 짧은 쪽, 그것도 같으면 먼저 후보에 오른 쪽. 한 사람 한 표이고 다시 투표하면 바뀜. 표가 하나도 없으면 마감 불가 |
| R9 | 같은 검색어는 10분 동안 저장해 둔 결과를 씀 |
| R10 | LLM 응답 검사: JSON이 아니면 버림. 가격이 R6 범위 밖이거나 목록에 없는 태그도 버림 |

태그 목록: 양 많음, 혼밥, 가성비, 빨리 나옴, 조용함, 단체 가능, 늦게까지 함, 매움

## 서버

```
브라우저 (HTML, CSS, JavaScript, 카카오맵 SDK)
    |  fetch
Express 서버
    |-- 계산 규칙 함수
    |-- 저장 모듈 --> JSON 파일
    |-- 카카오 로컬 API (가게 검색)
    |-- LLM API (한 줄에서 가격, 태그 뽑기)
```

### API

요청과 응답 형식은 만들기 전에 이슈에서 정하고 `docs/api.md`에 적습니다. 아래는 경로만 잡아 둔 것입니다.

| 메서드 | 경로 | 하는 일 |
| --- | --- | --- |
| GET | /api/health | 서버가 살아 있는지 |
| GET | /api/places/search?q= | 카카오 로컬 API로 가게 검색 (R9) |
| GET | /api/places | 기록이 있는 가게 목록. 필터와 정렬 (R1~R5) |
| GET | /api/places/:id | 가게 하나의 기록 수, 비율, 한 줄 추천 |
| POST | /api/reviews | 한 줄 추천 저장 (R6, R7) |
| POST | /api/reviews/draft | 한 줄을 받아 가격과 태그 초안을 돌려줌 (LLM, R10) |
| POST | /api/visits | "또 갈래요" 또는 "글쎄요" 저장 (R7) |
| POST | /api/rooms | 방 만들기 |
| GET | /api/rooms/:code | 방의 후보, 표, 마감 여부 |
| POST | /api/rooms/:code/votes | 투표 |
| POST | /api/rooms/:code/close | 마감하고 가게 정하기 (R8) |

### 저장하는 것

JSON 파일에 저장합니다.

- 가게: 카카오 장소 ID, 이름, 위도, 경도, 분류. 기록이 한 번이라도 남은 가게만
- 한 줄 추천: 가게, 문장, 가격, 태그, 익명 ID, 시각
- 응답: 가게, 또 갈래요 여부, 익명 ID, 방 코드(방에서 남긴 경우), 시각
- 방: 코드, 후보, 표, 마감 여부, 정해진 가게, 만든 사람의 익명 ID
- 시드 데이터: 팀원이 직접 가 본 가게. `data/seed/`에 넣어 저장소에 포함

파일을 읽고 쓰는 코드는 저장 모듈 한 곳에만 둡니다. 배포는 EC2에서 할 예정이라 파일이 남긴 하지만, 나중에 저장 방식을 바꾸게 되더라도 이 파일만 고치면 되게 하려는 것입니다.

API 키는 서버 환경 변수로만 두고 저장소에 올리지 않습니다. 브라우저에서 쓰는 카카오맵 키는 허용 도메인을 걸어 둡니다.

## LLM

쓰는 곳은 `POST /api/reviews/draft` 하나입니다.

- 보내는 것: 사용자가 쓴 한 줄, 가게 이름과 분류, 태그 목록
- 받는 것: `{ "price": 7000, "tags": ["양 많음", "혼밥"] }`
- 받은 값은 R10으로 걸러서 입력 칸에 채웁니다. 사용자가 저장을 눌러야 반영됩니다.
- 호출이 실패하거나 한도를 넘으면 칸을 비워 둡니다. 직접 입력해서 저장할 수 있고, 지도, 필터, 투표는 LLM을 쓰지 않습니다.

가게 추천이나 순위는 LLM에 맡기지 않고 저장된 기록과 위 규칙으로만 계산합니다.

## 배포

아직 팀에서 이야기하기 전인 계획입니다.

- AWS EC2 한 대에서 Docker 컨테이너로 Express 서버를 실행합니다.
- 데이터 폴더는 컨테이너 밖 볼륨에 두고 환경 변수 `DATA_DIR`로 연결합니다. 컨테이너를 새로 만들어도 기록이 남게 하려는 것입니다.
- API 키는 EC2의 환경 변수로만 넣습니다.
- 카카오맵 JavaScript 키에는 배포 주소를 허용 도메인으로 등록합니다.
- PR마다 테스트를 돌리는 것은 GitHub Actions로 할 생각입니다. 머지하면 자동으로 배포되게 하는 것은 수업 조건(자동 배포 서비스 금지)에 걸리는지 교수님께 확인한 뒤 정합니다.

## 개인정보

- 회원가입과 로그인이 없고, 이름, 학번, 연락처를 받지 않습니다.
- 브라우저에 처음 들어오면 무작위 익명 ID를 만들어 브라우저에 저장합니다. 같은 가게에 여러 번 기록하는 것을 막고, 투표를 한 사람 한 표로 세고, 방을 만든 사람을 알아보는 데 씁니다.
- 브라우저 저장소를 지우면 새 ID가 되므로 중복 기록을 완전히 막지는 못합니다.
- 한 줄 추천은 누구나 볼 수 있어서, 입력 칸에 이름이나 연락처를 쓰지 말라고 안내합니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```
npm install
cp .env.example .env    # 윈도우 명령 프롬프트에서는 copy .env.example .env
npm start
```

http://localhost:3000 으로 들어가면 됩니다. `.env`에 넣을 값은 `.env.example`에 적혀 있습니다.

가게 검색을 쓰려면 `.env`의 `KAKAO_REST_API_KEY`에 카카오 디벨로퍼스의 REST API 키를 넣어야 합니다. 그 앱에서 카카오맵 사용 설정도 켜야 하고, 꺼져 있으면 검색이 안 됩니다. 키가 없어도 서버는 켜지고 검색만 오류 안내가 나옵니다.

테스트는 `npm test`로 돌립니다. `tests` 폴더에서 이름이 `.test.js`로 끝나는 파일이 실행됩니다.

### 폴더

| 폴더 | 들어가는 것 |
| --- | --- |
| `public/` | 화면. HTML, CSS, JavaScript |
| `server/` | Express 서버. `app.js`가 앱, `index.js`가 실행, `routes/`에 API |
| `shared/` | 계산 규칙 함수(R1~R10). 화면 코드와 섞지 않습니다 |
| `data/seed/` | 저장소에 포함하는 시드 데이터 |
| `tests/` | 테스트 |
| `docs/` | API 문서 등 |

실행 중에 서버가 쓰는 데이터는 `data/runtime/`에 생기고 저장소에는 올라가지 않습니다.
