# 시드 데이터 넣기

처음 들어온 사람이 빈 지도를 보지 않게, 팀원이 직접 가 본 가게의 기록을 저장소에 넣어 둡니다(#14). 가게 번호와 좌표를 손으로 적기 어려워서, 입력 파일 하나만 채우면 스크립트가 `data/seed`의 파일을 만들어 줍니다.

## 순서

1. `data/seed-input.example.json`을 복사해서 `data/seed-input.json`으로 만듭니다. 이미 있으면 그 파일에 이어서 적습니다.
2. 아래 "적는 법"대로 기록을 적습니다.
3. `.env`에 `KAKAO_REST_API_KEY`가 있는지 확인하고 실행합니다.

```
npm run seed
```

4. 틀린 곳이 있으면 몇 번째 줄이 왜 틀렸는지 나오고 파일은 바뀌지 않습니다. 고쳐서 다시 실행합니다.
5. 잘 되면 `data/seed/places.json`, `reviews.json`, `visits.json`이 새로 써집니다. `data/seed-input.json`과 같이 커밋합니다.

`data/seed`의 파일은 스크립트가 통째로 다시 쓰기 때문에 직접 고치지 않습니다. 고칠 것이 있으면 `data/seed-input.json`을 고치고 다시 실행합니다.

다른 곳에 써서 미리 보고 싶으면 입력 파일과 폴더를 적습니다.

```
npm run seed -- data/seed-input.json 미리보기폴더
```

## 적는 법

기록 하나가 `{ }` 하나입니다.

```json
{
  "place": "카카오맵에 적힌 가게 이름",
  "text": "직접 먹어 보고 느낀 것을 한 줄로 적습니다",
  "menu": "먹은 메뉴",
  "price": 8000,
  "tags": ["양 많음", "혼밥"],
  "again": true,
  "date": "2026-11-20",
  "writer": "A"
}
```

| 칸 | 꼭 적나 | 내용 |
| --- | --- | --- |
| `place` | 꼭 | 가게 이름. 카카오맵에 적힌 이름으로 적습니다 |
| `placeId` | 필요할 때만 | 같은 이름의 가게가 여럿이라 못 정했을 때. 스크립트가 보여 주는 후보의 번호를 적습니다 |
| `text` | `again`이 없으면 꼭 | 한 줄 추천. 5자에서 100자 (R6) |
| `menu` | 선택 | 먹은 메뉴. 20자까지 |
| `price` | 선택 | 1인 가격. 1,000에서 100,000 사이 정수 (R6) |
| `tags` | 선택 | 3개까지. 양 많음, 혼밥, 가성비, 빨리 나옴, 조용함, 단체 가능, 늦게까지 함, 매움, 청결함 중에서 |
| `again` | `text`가 없으면 꼭 | 다녀왔어요 응답. 또 갈래요면 `true`, 글쎄요면 `false` |
| `date` | 꼭 | 다녀온 날. `2026-11-20` 모양이고 오늘까지 |
| `writer` | 꼭 | 쓴 사람을 구분하는 이름표. `A`, `B`처럼 적습니다. 실제 이름은 적지 않습니다 |

- `text`와 `again`을 같이 적으면 한 줄 추천과 다녀왔어요 응답이 둘 다 만들어집니다. `again`만 적으면 다녀왔어요 응답만 만들어집니다.
- 같은 사람이 같은 가게에 같은 날 두 번 적을 수 없습니다(R7과 같은 기준).
- 실제로 다녀온 것만 적습니다. 지어낸 기록은 넣지 않습니다.
- 실제 이름, 연락처 같은 개인정보는 넣지 않습니다. 이름표는 익명 ID를 만들 때만 쓰고, 만든 파일에는 `seed-`로 시작하는 글자로 바뀌어 들어갑니다. 다만 `data/seed-input.json`에는 이름표가 그대로 남습니다.

## 알아 둘 것

- 가게는 서버의 가게 검색과 같은 방식으로 찾습니다. 학교에서 1km 안의 음식점과 카페만 찾힙니다.
- 걸어서 15분(R2)이 넘는 가게는 넣을 수는 있지만 지도 목록에는 나오지 않습니다. 실행하면 그런 가게를 알려 줍니다.
- 또 갈래요 비율은 한 가게에 교내 인증된 응답이 3개 이상이어야 나옵니다. 그보다 적으면 "기록 부족"으로 보입니다.
- 시드의 기록은 교내 인증된 것으로 넣습니다. 인증되지 않은 응답은 비율에 들어가지 않는데, 시드는 팀원이 직접 다녀온 기록만 넣기 때문입니다.
- 서버는 `/data`에 같은 이름의 파일이 없을 때만 시드를 읽습니다. 배포 서버에 반영하는 방법은 [배포 문서](deploy.md)의 "8. 기록 백업, 지우기, 시드"에 있습니다.
