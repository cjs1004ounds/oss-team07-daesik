# API 형식

중간발표(11/19) 첫 기능에 쓰는 API만 적었습니다. 나머지는 만들기 전에 이슈에서 정하고 여기에 추가합니다.

아직 초안입니다. 맡은 API가 쓰기 불편하면 PR이나 이슈에서 말해 주세요.

## 공통

- 요청 본문과 응답은 JSON입니다.
- 위도와 경도는 숫자이고 이름은 `lat`, `lng`입니다. 카카오는 문자열 `y`, `x`로 주는데 서버에서 바꿔서 내보냅니다.
- 시각은 `createdAt`이고 `2026-11-19T03:20:00.000Z` 같은 ISO 문자열입니다.
- 오류가 나면 상태 코드와 함께 아래 형식으로 돌려줍니다.

```json
{ "error": "검색어를 입력해 주세요." }
```

| 상태 코드 | 언제 |
| --- | --- |
| 400 | 보낸 값이 잘못됨 |
| 404 | 없는 가게, 없는 경로 |
| 500 | 서버에서 오류가 남 |
| 502 | 카카오 API 호출이 실패함 |

## 저장하는 것

가게. `id`는 카카오 장소 ID이고 문자열입니다.

```json
{
  "id": "12345678",
  "name": "광운식당",
  "lat": 37.6195,
  "lng": 127.0589,
  "category": "음식점 > 한식"
}
```

`category`는 카카오가 주는 분류 문자열을 그대로 넣습니다. `음식점 > 한식 > 국밥 > 상호`처럼 2~4단계로 오고 길이가 가게마다 다릅니다.

한 줄 추천. `id`는 저장할 때 서버가 무작위로 만드는 값(UUID)입니다. `price`는 안 적었으면 `null`, `tags`는 없으면 빈 배열입니다.

```json
{
  "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
  "placeId": "12345678",
  "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
  "price": 7000,
  "tags": ["양 많음", "혼밥"],
  "anonId": "브라우저가 만든 익명 ID",
  "createdAt": "2026-11-19T03:20:00.000Z"
}
```

위 숫자와 이름은 예시로 지어낸 값입니다.

## GET /api/places/search?q=검색어

카카오 로컬 API로 가게를 검색합니다. 같은 검색어는 10분 동안 저장해 둔 결과를 돌려줍니다(R9).

응답 200

```json
{
  "places": [
    {
      "id": "12345678",
      "name": "광운식당",
      "lat": 37.6195,
      "lng": 127.0589,
      "category": "음식점 > 한식",
      "address": "서울 노원구 ..."
    }
  ]
}
```

- 결과가 없으면 `places`가 빈 배열입니다.
- 검색어가 비어 있으면 400
- 카카오 키가 없거나 카카오 호출이 실패하면 502

`address`는 검색 결과에서 가게를 구분하려고 보여 주는 값이고 저장하지는 않습니다.

## POST /api/reviews

한 줄 추천을 저장합니다. 처음 기록되는 가게면 가게도 같이 저장합니다.

요청

```json
{
  "place": {
    "id": "12345678",
    "name": "광운식당",
    "lat": 37.6195,
    "lng": 127.0589,
    "category": "음식점 > 한식"
  },
  "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
  "price": 7000,
  "tags": ["양 많음", "혼밥"],
  "anonId": "브라우저가 만든 익명 ID"
}
```

응답 201

```json
{
  "review": {
    "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
    "placeId": "12345678",
    "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
    "price": 7000,
    "tags": ["양 많음", "혼밥"],
    "createdAt": "2026-11-19T03:20:00.000Z"
  }
}
```

- R6 검사에 걸리면 400과 이유
- `place`를 통째로 받는 이유: 가게를 저장하려고 서버가 카카오를 다시 호출하지 않아도 되게 하려는 것입니다. 대신 브라우저가 보낸 가게 정보를 그대로 믿게 됩니다. 문제가 되면 서버가 `id`로 다시 확인하는 방식으로 바꿉니다.

## GET /api/places

기록이 있는 가게 목록입니다. 중간발표까지는 필터와 정렬 없이 전부 돌려줍니다.

응답 200

```json
{
  "places": [
    {
      "id": "12345678",
      "name": "광운식당",
      "lat": 37.6195,
      "lng": 127.0589,
      "category": "음식점 > 한식",
      "reviewCount": 2
    }
  ]
}
```

## GET /api/places/:id

가게 하나와 그 가게의 한 줄 추천입니다.

응답 200

```json
{
  "place": {
    "id": "12345678",
    "name": "광운식당",
    "lat": 37.6195,
    "lng": 127.0589,
    "category": "음식점 > 한식"
  },
  "reviews": [
    {
      "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
      "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
      "price": 7000,
      "tags": ["양 많음", "혼밥"],
      "createdAt": "2026-11-19T03:20:00.000Z"
    }
  ]
}
```

- 없는 가게면 404
- 응답에는 `anonId`를 넣지 않습니다.

## 검색 화면에서 작성 화면으로 가게 넘기기

검색 화면에서 가게를 고르면 그 가게를 `sessionStorage`에 `selectedPlace`라는 이름으로 넣고 작성 화면으로 이동합니다.

```js
// 검색 화면
sessionStorage.setItem('selectedPlace', JSON.stringify(place));

// 작성 화면
const place = JSON.parse(sessionStorage.getItem('selectedPlace'));
```

넣는 값은 `id`, `name`, `lat`, `lng`, `category`입니다. 작성 화면은 이 값을 그대로 POST /api/reviews의 `place`에 넣으면 됩니다. 값이 없으면(주소를 직접 쳐서 들어온 경우) 검색 화면으로 돌려보냅니다.
