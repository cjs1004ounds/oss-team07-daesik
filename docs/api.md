# API 형식

중간발표(11/19) 첫 기능에 쓰는 API만 적었습니다. 나머지는 만들기 전에 이슈에서 정하고 여기에 추가합니다.

아직 초안입니다. 맡은 API가 쓰기 불편하면 PR이나 이슈에서 말해 주세요.

## 공통

- 요청 본문과 응답은 JSON입니다.
- 위도와 경도는 숫자이고 이름은 `lat`, `lng`입니다. 카카오는 문자열 `y`, `x`로 주는데 서버에서 바꿔서 내보냅니다.
- 시각은 `createdAt`이고 `2026-11-19T03:20:00.000Z` 같은 ISO 문자열입니다.
- 오류가 나면 상태 코드와 함께 아래 형식으로 돌려줍니다.

```json
{ "error": "검색어를 입력해 주세요." }
```

| 상태 코드 | 언제 |
| --- | --- |
| 400 | 보낸 값이 잘못됨 |
| 404 | 없는 가게, 없는 경로 |
| 500 | 서버에서 오류가 남 |
| 502 | 카카오 API 호출이 실패함 |

## 저장하는 것

가게. `id`는 카카오 장소 ID이고 문자열입니다.

```json
{
  "id": "12345678",
  "name": "광운식당",
  "lat": 37.6195,
  "lng": 127.0589,
  "category": "음식점 > 한식"
}
```

`category`는 카카오가 주는 분류 문자열을 그대로 넣습니다. `음식점 > 한식 > 국밥 > 상호`처럼 2~4단계로 오고 길이가 가게마다 다릅니다.

한 줄 추천. `id`는 저장할 때 서버가 무작위로 만드는 값(UUID)입니다. `price`는 안 적었으면 `null`, `tags`는 없으면 빈 배열입니다.

```json
{
  "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
  "placeId": "12345678",
  "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
  "price": 7000,
  "tags": ["양 많음", "혼밥"],
  "anonId": "브라우저가 만든 익명 ID",
  "createdAt": "2026-11-19T03:20:00.000Z"
}
```

위 숫자와 이름은 예시로 지어낸 값입니다.

## LLM 호출 제한

LLM(Gemini)을 부르는 API는 모두 `server/llm.js`를 거치고, 여기서 횟수를 셉니다. 누가 일부러 많이 부르게 만들어도 한도가 바닥나지 않게 하려는 것입니다.

- 하루 한도: 서버 전체에서 하루(한국 시간)에 500번. `.env`의 `LLM_DAILY_LIMIT`로 바꿉니다.
- 사람별 한도: 같은 접속 IP 때문에 LLM을 부르는 횟수는 1시간에 40번까지
- 한도를 넘으면 LLM 없이 동작합니다. 신고는 신고 수로 정하고, 검색은 원래 결과만 돌려줍니다.
- 검색어는 50자까지 받습니다. 넘으면 400

## GET /api/config

브라우저가 화면을 그릴 때 필요한 설정입니다. 지금은 카카오맵을 띄울 때 쓰는 JavaScript 키 하나입니다.

응답 200

```json
{ "kakaoJsKey": "카카오 JavaScript 키" }
```

- 서버에 `KAKAO_JS_KEY`가 없으면 `kakaoJsKey`가 빈 문자열입니다. 이때 화면은 지도 대신 안내 문구를 보여 줍니다.
- 브라우저에 보여도 되는 값만 넣습니다. REST 키 같은 서버용 키는 넣지 않습니다.

## GET /api/places/search?q=검색어

카카오 로컬 API로 학교 근처 음식점(FD6)과 카페(CE7)를 검색합니다. 두 분류를 같이 찾아 학교에서 가까운 순으로 합치고 20곳까지 씁니다. 같은 검색어는 10분 동안 저장해 둔 결과를 씁니다(R9).

응답 200

```json
{
  "places": [
    {
      "id": "12345678",
      "name": "광운식당",
      "lat": 37.6195,
      "lng": 127.0589,
      "category": "음식점 > 한식",
      "address": "서울 노원구 ..."
    }
  ]
}
```

- 결과가 없으면 `places`가 빈 배열입니다.
- 검색어가 비어 있으면 400
- 카카오 키가 없거나 카카오 호출이 실패하면 502

`address`는 검색 결과에서 가게를 구분하려고 보여 주는 값이고 저장하지는 않습니다.

우리 기록(한 줄 추천의 문장, 먹은 메뉴 칸이 생기면 그 칸도)에 검색어가 들어 있는 가게는 카카오 결과 앞에 붙고 `"fromRecords": true`가 붙습니다. 카카오는 가게 이름과 분류로만 찾아서, 이렇게 해야 "제육"으로 제육이 대표 메뉴가 아닌 가게도 나옵니다.

```json
{
  "places": [
    {
      "id": "12345678",
      "name": "광운식당",
      "lat": 37.6195,
      "lng": 127.0589,
      "category": "음식점 > 한식",
      "address": "",
      "fromRecords": true
    }
  ]
}
```

- 띄어쓰기는 무시하고 찾습니다. "제 육"도 "제육"과 같습니다.
- 맞는 기록이 많은 가게가 앞이고, 같으면 최근 기록이 있는 가게가 앞입니다. 10곳까지만 붙입니다.
- 카카오 결과에도 있는 가게는 한 번만 나오고 카카오의 주소를 씁니다. 기록으로만 찾은 가게는 주소를 저장하지 않아서 `address`가 빈 문자열입니다.
- 카카오 결과는 10분 동안 저장해 두지만 기록에서 찾는 것은 매번 해서, 방금 남긴 기록도 바로 찾힙니다.
- 카카오 호출이 실패해도 기록으로 찾은 가게가 있으면 200으로 그것만 돌려줍니다.

결과가 10곳보다 적으면 LLM(Gemini)에게 넓힌 검색어를 받아 한 번 더 찾습니다(`shared/searchExpand.js`). 카카오는 "제육"으로는 윤스쿡을 주지 않지만 "제육볶음"으로는 줍니다. 이런 경우를 메우려는 것입니다.

- LLM은 실제 메뉴 이름이나 가게 종류로 된 검색어를 4개까지 만듭니다. 예: 제육 -> 제육볶음, 제육덮밥. 가게는 늘 카카오와 우리 기록에서 찾고, LLM이 가게를 지어내지는 않습니다.
- 넓힌 검색어로 찾은 가게는 원래 결과 뒤에 붙고 `"via": "제육볶음"`처럼 어떤 검색어로 찾았는지가 붙습니다. 이미 있는 가게는 다시 넣지 않습니다.
- 같은 검색어의 넓힌 결과는 하루 동안 저장해 두고 LLM을 다시 부르지 않습니다. 실패한 결과(빈 목록)도 하루 동안 저장합니다.
- LLM은 4초까지만 기다립니다. 키가 없거나 실패하면 원래 결과만 돌려줍니다.
- 원래 검색어로 카카오 호출이 실패했으면 넓히지 않습니다.
- 한 번에 30곳까지 돌려줍니다.

## POST /api/reviews

한 줄 추천을 저장합니다. 처음 기록되는 가게면 가게도 같이 저장합니다.

요청

```json
{
  "place": {
    "id": "12345678",
    "name": "광운식당",
    "lat": 37.6195,
    "lng": 127.0589,
    "category": "음식점 > 한식"
  },
  "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
  "price": 7000,
  "tags": ["양 많음", "혼밥"],
  "anonId": "브라우저가 만든 익명 ID"
}
```

응답 201

```json
{
  "review": {
    "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
    "placeId": "12345678",
    "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
    "price": 7000,
    "tags": ["양 많음", "혼밥"],
    "verified": true,
    "createdAt": "2026-11-19T03:20:00.000Z"
  }
}
```
- 저장할 때 교내 인증이 유효한 익명 ID면 `"verified": true`, 아니면 `false`가 붙습니다.
- R6 검사에 걸리면 400과 이유
- 같은 익명 ID가 같은 가게에 오늘(한국 시간) 이미 한 줄 추천을 남겼으면 409와 안내 문구 (R7). 이때는 저장하지 않습니다.
- `place`를 통째로 받는 이유: 가게를 저장하려고 서버가 카카오를 다시 호출하지 않아도 되게 하려는 것입니다. 대신 브라우저가 보낸 가게 정보를 그대로 믿게 됩니다. 문제가 되면 서버가 `id`로 다시 확인하는 방식으로 바꿉니다.

## POST /api/visits

"또 갈래요"(`again: true`) 또는 "글쎄요"(`again: false`) 응답을 저장합니다. 저장 시점의 교내 인증 여부(`verified`)도 함께 기록됩니다.

요청

```json
{
  "placeId": "12345678",
  "again": true,
  "anonId": "브라우저가 만든 익명 ID"
}
```

- 처음 기록되는 가게면 `placeId` 대신 `place` 객체(`id`, `name`, `lat`, `lng`, `category`)를 함께 보낼 수 있습니다.
- `place`와 `placeId`를 둘 다 보내면 `place.id`가 우선으로 사용됩니다.
- 같이 정하기 방에서 남긴 경우에만 `"roomCode": "방 코드"`를 함께 보냅니다. 일반 지도 화면에서는 생략합니다.

응답 201

```json
{
  "visit": {
    "id": "8a1b2c3d-4e5f-6789-abcd-ef0123456789",
    "placeId": "12345678",
    "again": true,
    "roomCode": null,
    "verified": true,
    "createdAt": "2026-11-24T00:00:00.000Z"
  }
}
```

- 응답에는 `anonId`를 넣지 않습니다.
- `again`이 `true`/`false`가 아니거나 `anonId`가 없으면 400
- 등록되지 않은 `placeId`만 보냈으면 404
- 같은 익명 ID가 같은 가게에 오늘(한국 시간) 이미 응답을 남겼으면 409와 안내 문구 (R7)

## 기록 시간 가중치 (R14)

`GET /api/places`와 `GET /api/places/:id`가 돌려주는 비율, 가격, 마지막 기록은 최근 기록일수록 크게 반영한 값입니다(`shared/recordWeight.js`).

- 무게 = 0.5 ^ (지난 날수 / 90). 오늘 1, 90일 전 0.5, 180일 전 0.25. 365일이 지나면 넣지 않습니다.
- `againRatio`: "또 갈래요" 비율(0~100 정수). 교내 인증된 응답만 넣고, 넣을 응답이 3개보다 적으면 `null`("기록 부족")
- `responseCount`: 비율에 넣은 응답 수 (교내 인증, 365일 안)
- `averagePrice`: 1인 가격 평균. 가격이 적힌 한 줄 추천을 같은 무게로 평균 내고 100원 단위로 반올림. 없으면 `null`
- `lastRecordAt`: 가장 최근 한 줄 추천이나 응답의 시각. 숨긴 글은 빼고, 없으면 `null`

## GET /api/places

기록이 있는 가게 목록입니다. 학교에서 걸어서 15분이 넘는 가게는 빼고 돌려줍니다(R1, R2). 쿼리를 보내면 가격 상한, 음식 종류, 태그로 거릅니다(R3). 정렬(R5)은 아직 없습니다.

```
GET /api/places?maxPrice=8000&category=한식&tags=혼밥,가성비
```

쿼리는 모두 선택입니다.

| 쿼리 | 뜻 |
| --- | --- |
| `maxPrice` | 1인 가격 상한(원). 숫자만 받습니다. `averagePrice`가 이 값 이하인 가게만 남고, 가격 기록이 없는 가게는 빠집니다 |
| `category` | 음식 종류. 카카오 분류의 둘째 단계(`한식`, `일식`, `분식` 등)와 비교합니다 |
| `tags` | 쉼표로 나눈 태그. 여러 개를 보내면 모두 나온 가게만 남습니다 |

응답 200

```json
{
  "places": [
    {
      "id": "12345678",
      "name": "광운식당",
      "lat": 37.6195,
      "lng": 127.0589,
      "category": "음식점 > 한식",
      "reviewCount": 2,
      "responseCount": 4,
      "againRatio": 67,
      "averagePrice": 8000,
      "lastRecordAt": "2026-11-25T03:00:00.000Z",
      "walkMinutes": 4,
      "tags": ["혼밥", "가성비"]
    }
  ]
}
```

- `walkMinutes`: 학교 기준점에서 가게까지 직선거리를 67m에 1분으로 나눠 올린 값입니다. 직선거리라 실제보다 짧게 나오는 어림값입니다.
- `tags`: 그 가게의 한 줄 추천에 한 번이라도 나온 태그입니다. 숨긴 글의 태그는 넣지 않습니다.
- 맞는 가게가 없으면 `places`가 빈 배열입니다.
- `maxPrice`가 숫자가 아니면 400 `{ "error": "가격 상한은 숫자로 보내 주세요." }`

학교 기준점은 아직 정하지 않아서 지도 가운데와 같은 값(37.61924, 127.05827)을 씁니다(`shared/placeFilter.js`의 `SCHOOL`).

## GET /api/places/:id

가게 하나와 그 가게의 한 줄 추천입니다.

응답 200

```json
{
  "place": {
    "id": "12345678",
    "name": "광운식당",
    "lat": 37.6195,
    "lng": 127.0589,
    "category": "음식점 > 한식"
  },
  "summary": "양이 많고 혼밥하기 좋다는 기록이 많아요",
  "stats": {
    "responseCount": 4,
    "againRatio": 67,
    "averagePrice": 8000,
    "lastRecordAt": "2026-11-25T03:00:00.000Z"
  },
  "reviews": [
    {
      "id": "3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f",
      "text": "제육 7천원인데 양 많음 혼밥하기 좋음",
      "price": 7000,
      "tags": ["양 많음", "혼밥"],
      "createdAt": "2026-11-19T03:20:00.000Z"
    }
  ]
}
```
- 한 줄 추천은 최근에 남긴 것이 앞에 옵니다.
- 없는 가게면 404
- 응답에는 `anonId`를 넣지 않습니다.

`summary`는 그 가게의 한 줄 추천들을 LLM이 한 문장으로 정리한 요약입니다(`shared/placeSummary.js`).

- 숨기지 않은 추천이 2개 이상일 때만 만들고, 아니면 `null`
- 최근 추천 20개까지 보냅니다. 익명 ID는 보내지 않습니다.
- 만든 요약은 가게에 저장해 두고, 추천이 새로 생기거나 숨겨졌을 때만 다시 만듭니다. 같은 가게를 동시에 열어도 한 번만 만듭니다.
- LLM은 4초까지만 기다립니다. 실패하거나 한도를 넘으면 `null`이고 나머지는 그대로 나옵니다.

## POST /api/verify

교내 인증입니다. 학교 와이파이로 접속했으면 위치 없이 통과하고(R12), 아니면 보낸 위치로 판정합니다(R11). 한 번 인증하면 30일 유지됩니다(R13).

요청

```json
{ "anonId": "브라우저가 만든 익명 ID", "lat": 37.6201, "lng": 127.058, "accuracy": 35 }
```

- `lat`, `lng`, `accuracy`는 브라우저 위치(`navigator.geolocation`)에서 받은 값입니다. `accuracy`는 오차(m)입니다.
- 화면은 먼저 `anonId`만 보냅니다. 학교 와이파이면 여기서 끝나서 위치 권한을 묻지 않아도 됩니다.

응답 200

```json
{
  "verified": true,
  "method": "wifi",
  "verifiedAt": "2026-11-23T03:00:00.000Z",
  "expiresAt": "2026-12-23T03:00:00.000Z"
}
```

- `method`는 `wifi` 또는 `location`입니다.
- 학교 와이파이가 아니고 위치도 안 보냈으면 403과 `"needLocation": true`. 화면은 이때 위치를 물어보고 다시 보냅니다.
- 캠퍼스 밖이거나 오차가 150m보다 크면 403과 이유
- 익명 ID가 없거나 좌표가 숫자가 아니면 400
- 다시 인증하면 시각과 방법이 새로 바뀝니다.

저장하는 것은 아래 세 가지뿐입니다. 좌표와 IP는 판정에만 쓰고 저장하지 않습니다.

```json
{ "anonId": "브라우저가 만든 익명 ID", "method": "wifi", "verifiedAt": "2026-11-23T03:00:00.000Z" }
```

학교 대역은 서버 환경 변수 `CAMPUS_IP_PREFIXES`로 정합니다. 서버는 nginx가 붙여 주는 `X-Forwarded-For`에서 실제 접속 IP를 읽습니다(`server/app.js`의 `trust proxy`).

## GET /api/verify/:anonId

이 익명 ID가 지금 교내 인증돼 있는지입니다.

응답 200

```json
{
  "verified": true,
  "method": "wifi",
  "verifiedAt": "2026-11-23T03:00:00.000Z",
  "expiresAt": "2026-12-23T03:00:00.000Z"
}
```

- 인증한 적이 없거나 30일이 지났으면 `{ "verified": false }`
- 다른 API에서 인증 여부가 필요하면 저장 모듈의 `store.isVerified(anonId)`를 씁니다.

## POST /api/reviews/check

한 줄 추천을 저장하기 전에 문제 될 내용이 있는지 알려 줍니다. 저장하지는 않습니다. 작성 화면은 저장 버튼을 누르면 먼저 이걸 부르고, 걸린 게 있으면 그래도 저장할지 묻습니다.

요청

```json
{ "text": "사장님 번호 010-1234-5678", "placeName": "윤스쿡" }
```

응답 200

```json
{
  "issues": [{ "kind": "personal", "message": "전화번호가 들어 있어요." }],
  "checkedBy": ["rules", "llm"]
}
```

- `kind`: `personal`(개인정보), `abuse`(욕설, 비방), `ad`(광고), `unrelated`(가게와 상관없음), `unfounded`(근거 없는 단정)
- 전화번호, 이메일, 학번처럼 보이는 숫자는 규칙으로 찾고(`shared/reviewCheck.js`), 나머지는 LLM에게 묻습니다.
- LLM이 없거나 실패하면 `checkedBy`가 `["rules"]`이고 규칙 결과만 돌려줍니다.
- 같은 종류는 한 번만, 3개까지 돌려줍니다.
- `text`가 없거나 100자를 넘으면 400

## POST /api/reports

한 줄 추천을 신고합니다. 신고 수와 LLM 판단으로 숨길지 정합니다(R15).

요청

```json
{ "reviewId": "한 줄 추천 id", "anonId": "신고한 사람의 익명 ID" }
```

응답 201

```json
{
  "report": { "id": "5c1d...", "reviewId": "3f2a9c1e-...", "createdAt": "2026-11-25T09:00:00.000Z" },
  "hidden": false
}
```

- `hidden`이 `true`면 이번 신고로 그 글이 숨겨진 것입니다.
- 같은 사람이 같은 글을 두 번 신고하거나, 이미 숨겨진 글이면 409
- 없는 글이면 404, `reviewId`나 `anonId`가 없으면 400

숨기는 경우

- 교내 인증한 서로 다른 사람 3명이 신고했을 때. 인증은 신고할 때의 상태로 셉니다.
- 신고가 1건이라도 있고, LLM이 그 글을 악의적(`malicious`)이라고 판단했을 때

LLM 판단

- 글마다 처음 신고가 들어올 때 한 번만 묻고, 결과를 그 글에 저장해 둡니다. 호출이 실패했으면 다음 신고 때 다시 묻습니다.
- 가게 이름과 글만 보냅니다. 익명 ID는 보내지 않습니다.
- 받은 답은 `shared/moderation.js`로 검사해서 `verdict`가 `malicious`, `ok`, `unsure` 중 하나일 때만 씁니다.
- 키(`GEMINI_API_KEY`)가 없거나 호출이 실패하면 신고 수로만 정합니다. 신고는 그대로 저장됩니다.

숨긴 글은 지우지 않고 `hidden: true`만 표시해 둡니다. `GET /api/places`의 `reviewCount`, `GET /api/places/:id`의 `reviews`, 메뉴로 찾기에서 빠집니다. 판단 결과와 숨긴 이유는 응답으로 내보내지 않습니다.

저장하는 신고는 아래 모양입니다.

```json
{ "id": "5c1d...", "reviewId": "3f2a9c1e-...", "anonId": "익명 ID", "verified": true, "createdAt": "2026-11-25T09:00:00.000Z" }
```

## 같이 정하기 방

방을 만든 사람이 후보 가게를 고르고, 링크를 받은 사람들이 투표하고, 만든 사람이 마감하면 가게가 정해집니다(R8). 실시간 통신은 쓰지 않고 화면이 몇 초마다 `GET /api/rooms/:code`를 다시 불러 갱신합니다.

방 코드는 헷갈리는 글자(0, O, 1, I)를 뺀 대문자와 숫자 6자리입니다. 소문자로 들어와도 같은 방으로 봅니다. 없는 방 코드는 모든 방 API에서 404입니다.

### POST /api/rooms

방을 만듭니다.

요청

```json
{
  "anonId": "만든 사람의 익명 ID",
  "candidates": [
    { "id": "12345678", "name": "광운식당", "lat": 37.6195, "lng": 127.0589, "category": "음식점 > 한식" },
    { "id": "87654321", "name": "광운분식", "lat": 37.6201, "lng": 127.0592, "category": "음식점 > 분식" }
  ]
}
```

- 후보는 검색 결과의 가게 모양 그대로 2~6곳입니다. 같은 가게를 두 번 넣으면 400
- 후보 순서가 후보에 오른 순서입니다. 표가 같으면 먼저 오른 가게로 정해집니다.
- 후보 가게는 방 안에만 저장합니다. 기록이 생기기 전에는 지도에 나오지 않습니다.

응답 201

```json
{
  "room": {
    "code": "K7PX2M",
    "candidates": [
      { "placeId": "12345678", "name": "광운식당", "lat": 37.6195, "lng": 127.0589, "category": "음식점 > 한식", "votes": 0 },
      { "placeId": "87654321", "name": "광운분식", "lat": 37.6201, "lng": 127.0592, "category": "음식점 > 분식", "votes": 0 }
    ],
    "totalVotes": 0,
    "closed": false,
    "winnerId": null,
    "createdAt": "2026-11-24T03:00:00.000Z",
    "closedAt": null
  }
}
```

- 응답에는 만든 사람과 투표한 사람의 익명 ID, 누가 어디에 투표했는지를 넣지 않습니다. 화면에서 내 표를 보여 주려면 브라우저에 따로 기억해 둡니다.
- 아래 방 API는 모두 이 `room` 모양으로 돌려줍니다.

### GET /api/rooms/:code

방의 후보, 후보별 표 수, 마감 여부입니다. 마감됐으면 `winnerId`에 정해진 가게의 `placeId`가 들어 있습니다.

### POST /api/rooms/:code/votes

투표합니다. 한 사람 한 표이고 다시 투표하면 바뀝니다(R8).

```json
{ "anonId": "익명 ID", "placeId": "12345678" }
```

- 200과 방
- 이 방의 후보가 아니거나 익명 ID가 없으면 400
- 마감된 방이면 409

### POST /api/rooms/:code/close

마감하고 가게를 정합니다(R8).

```json
{ "anonId": "만든 사람의 익명 ID" }
```

- 200과 `winnerId`가 들어간 방
- 방을 만든 사람이 아니면 403
- 표가 하나도 없거나 이미 마감됐으면 409
- 도보 시간(R1)이 아직 없어서 지금은 표가 같으면 먼저 후보에 오른 가게로 정해집니다.

저장하는 방은 아래 모양입니다. `votes`와 `ownerAnonId`는 응답으로 내보내지 않습니다.

```json
{
  "code": "K7PX2M",
  "candidates": [{ "placeId": "12345678", "name": "광운식당", "lat": 37.6195, "lng": 127.0589, "category": "음식점 > 한식" }],
  "votes": [{ "anonId": "익명 ID", "placeId": "12345678" }],
  "closed": false,
  "winnerId": null,
  "ownerAnonId": "만든 사람의 익명 ID",
  "createdAt": "2026-11-24T03:00:00.000Z",
  "closedAt": null
}
```

다녀온 뒤 "또 갈래요"나 "글쎄요"는 `POST /api/visits`에 `roomCode`를 붙여 남깁니다.

## 익명 ID

로그인이 없어서 브라우저마다 무작위 ID를 하나 만들어 씁니다. 같은 사람이 같은 가게에 여러 번 남기는 것을 막을 때(R7), 투표를 한 사람 한 표로 셀 때(R8) 씁니다.

- `localStorage`의 `anonId`라는 이름에 저장합니다.
- 처음 필요할 때 `crypto.randomUUID()`로 만듭니다. 이 함수가 없는 환경에서는 시각과 난수를 이어 붙인 문자열을 씁니다.
- 한 줄 추천, 다녀왔어요, 투표가 모두 같은 값을 씁니다. 새 화면에서도 같은 이름으로 꺼내 쓰면 됩니다.
- 브라우저 저장소를 지우면 새 ID가 되므로 중복을 완전히 막지는 못합니다.

```js
let anonId = localStorage.getItem('anonId');
if (!anonId) {
  anonId = crypto.randomUUID();
  localStorage.setItem('anonId', anonId);
}
```

## 검색 화면에서 작성 화면으로 가게 넘기기

검색 화면에서 가게를 고르면 그 가게를 `sessionStorage`에 `selectedPlace`라는 이름으로 넣고 작성 화면으로 이동합니다.

```js
// 검색 화면
sessionStorage.setItem('selectedPlace', JSON.stringify(place));

// 작성 화면
const place = JSON.parse(sessionStorage.getItem('selectedPlace'));
```

넣는 값은 `id`, `name`, `lat`, `lng`, `category`입니다. 작성 화면은 이 값을 그대로 POST /api/reviews의 `place`에 넣으면 됩니다. 값이 없으면(주소를 직접 쳐서 들어온 경우) 검색 화면으로 돌려보냅니다.
